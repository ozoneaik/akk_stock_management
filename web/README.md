# ออฟกิจเกษตร — เว็บแอปจัดการสต็อกสินค้า (มือถือ/iPad)

เวอร์ชันเว็บของระบบจัดการสต็อกสินค้า ออกแบบมาให้ใช้งานผ่านมือถือ/iPad เป็นหลัก
ใช้ฐานข้อมูล **TiDB (MySQL-compatible)** ตัวเดียวกับที่เก็บไว้ในโปรเจกต์นี้
(schema เดิมสร้างไว้ด้วย Prisma อยู่แล้วก่อนหน้านี้ — โปรเจกต์นี้ต่อยอดจาก schema เดิม)

## เทคโนโลยีที่ใช้

- Next.js 16 (App Router, Server Actions) + React 19 + TypeScript
- Prisma ORM 7.10.0 (คงเวอร์ชันนี้ไว้ก่อน — Prisma 8 ที่เป็นเวอร์ชันล่าสุดตอนนี้เปลี่ยนไปเป็น
  "Developer Platform" CLI แบบใหม่ทั้งหมด ยังไม่เหมาะกับโปรเจกต์ที่ต่อฐานข้อมูลของตัวเองแบบนี้)
- `@prisma/adapter-mariadb` — Prisma 7 ต้องต่อฐานข้อมูลผ่าน driver adapter เอง
- Tailwind CSS v4 (mobile-first)
- `jose` — เซ็น/ตรวจสอบ session cookie (JWT)

## เข้าสู่ระบบด้วย PIN

ระบบนี้ไม่ได้ใช้ username+password เหมือนเวอร์ชัน Desktop เพราะ schema เดิมออกแบบ column
`pin` ไว้สำหรับ login แบบกดตัวเลข 4 หลัก ซึ่งเหมาะกับหน้าจอสัมผัสมากกว่า — เข้าหน้า `/login`
แล้วแตะเลือกชื่อผู้ใช้ จากนั้นกดรหัส PIN

**บัญชีทดสอบ** (ตั้งไว้ตอน seed ข้อมูลใหม่ เปลี่ยนได้ที่หน้า "จัดการผู้ใช้งาน"):

| Username | PIN  | บทบาท |
|----------|------|--------|
| admin    | 9999 | แอดมิน (เห็นทุกอย่าง + จัดการผู้ใช้งาน + บันทึกกิจกรรม) |
| owner    | 1234 | เจ้าของร้าน (เหมือนแอดมินทุกอย่าง ยกเว้น 2 เมนูข้างต้น) |

## วิธีรัน

```bash
cd web
npm install          # ถ้ายังไม่เคย install
npm run dev
```

เปิด http://localhost:3000 (ทดสอบบนมือถือจริงในวง LAN เดียวกันได้ผ่าน URL "Network" ที่ dev server แสดง)

### ตัวแปรแวดล้อม (`.env`)

- `DATABASE_URL` — connection string ของ TiDB (ตั้งไว้แล้ว)
- `AUTH_SECRET` — คีย์ลับสำหรับเซ็น session — **ต้องเปลี่ยนเป็นค่าสุ่มยาวๆ ก่อนใช้งานจริง**
  (ตอนนี้เป็นค่า placeholder ที่ยังไม่ปลอดภัย)

### คำสั่งที่ใช้บ่อย

```bash
npx prisma db pull      # ดึงโครงสร้างตารางล่าสุดจากฐานข้อมูลจริงมาที่ schema.prisma
npx prisma generate     # สร้าง Prisma Client ใหม่หลังแก้ schema
npx tsx prisma/seed.ts  # ใส่ข้อมูลตัวอย่าง (ทำงานเฉพาะตอนตาราง User ว่างเปล่า)
npm run build           # build production (เช็ค type error/compile error ทั้งโปรเจกต์)
```

## โครงสร้างโปรเจกต์

```
web/
├── prisma/
│   ├── schema.prisma     # โครงสร้างฐานข้อมูล (ตรงกับ TiDB จริง)
│   └── seed.ts           # ข้อมูลตัวอย่างเริ่มต้น
├── src/
│   ├── app/
│   │   ├── login/             # หน้าเข้าสู่ระบบ (เลือกผู้ใช้ + PIN pad)
│   │   ├── (app)/              # ทุกหน้าหลังล็อกอิน มี bottom nav ร่วมกัน
│   │   │   ├── page.tsx              # ภาพรวม (Dashboard)
│   │   │   ├── products/             # รายการ/รายละเอียด/เพิ่ม/แก้ไขสินค้า
│   │   │   ├── stock/                 # ปรับสต็อกทีละหลายรายการ
│   │   │   ├── users/                 # จัดการผู้ใช้งาน (admin เท่านั้น)
│   │   │   ├── activity/              # บันทึกกิจกรรม (admin เท่านั้น)
│   │   │   └── more/                  # เมนู: ข้อมูลผู้ใช้ + ลิงก์ admin + logout
│   │   └── actions/            # Server Actions (auth, products, stock, users)
│   ├── components/         # UI ที่ใช้ร่วมกันหลายหน้า
│   ├── lib/                # prisma client, session/auth, activity log helper
│   └── proxy.ts            # กันเข้าหน้าในระบบโดยไม่ login (เดิมชื่อ middleware.ts)
```

## สิ่งที่ยังไม่ได้ทำ (ขอบเขตที่ตัดไว้รอบนี้)

- **แอป Desktop (Python/Tkinter) ยังไม่ได้ย้ายมาต่อฐานข้อมูล TiDB นี้** — ยังใช้ SQLite ของตัวเองอยู่
  ต้องแก้ `database/db.py` และ `models/*.py` ของฝั่ง Desktop ให้คุยกับ MySQL/TiDB แทน ถ้าต้องการให้
  ทั้งสองระบบใช้ข้อมูลชุดเดียวกันจริงๆ ตามที่วางแผนไว้ (เป็นงานแยกที่ควรทำเป็นรอบถัดไป)
- ยังไม่มี UI สำหรับ sync ช่องทางขาย (`ChannelStockMapping`) และระบบแชท (`ChatConversation`/`ChatMessage`)
  — ตาราง/schema มีอยู่แล้วในฐานข้อมูล แต่ยังไม่ได้สร้างหน้าจอใช้งาน (เป้าหมายระยะถัดไปตามที่ README
  ฝั่ง Desktop วางแผนไว้)
- การอัปโหลดรูปสินค้าใช้วิธีกรอกลิงก์ URL เท่านั้น (ยังไม่มีระบบอัปโหลดไฟล์ เพราะต้องมี object storage
  เช่น S3/Vercel Blob เพิ่มเติม)
- ราคาสินค้ารองรับเฉพาะราคาช่องทาง "หน้าร้าน" ในหน้าแก้ไข ยังไม่มี UI จัดการส่วนลด/ราคาตามช่วงเวลา
  ต่อช่องทางอื่น (ข้อมูลใน schema รองรับอยู่แล้ว เพิ่ม UI ทีหลังได้)
